# SoundOps — Image לכרטיס SD

צורבים כרטיס, מכניסים לפיי, מחברים לחשמל ולרשת. תוך כמה דקות המכשיר מופיע בדשבורד ב"מכשירים ממתינים" (`soundops-xxxxxx` + קוד שיוך), משייכים לסניף, וזהו. אין צורך במסך, מקלדת או SSH.

מה יש בכרטיס:
- Raspberry Pi OS Lite 64-bit (Trixie). מתאים ל-Pi 4 ו-Pi 5, וגם ל-Pi 3B+.
- הנגן (`music_agent`) על tag משוחרר, עם כל החבילות מותקנות מראש: VLC, PipeWire, בלוטוס, Python venv, yt-dlp ו-Deno. כך המכשיר לא צריך apt ברשת של החנות.
- Tailscale מותקן ולא מחובר. אחרי השיוך לסניף השרת מחבר אותו לבד לחשבון שלך, ראו למטה.
- SSH עם המפתח שלך בלבד (`id_ed25519.pub` מהמחשב שבנה את ה-Image). סיסמת `pi` נעולה.
- ריבוט לילי ב-00:00, עדכון yt-dlp שבועי, אזור זמן ירושלים, Wi-Fi באזור IL, ולוגים שנשמרים אחרי ריבוט.

**אין בכרטיס סודות.** אין בו token של מכשיר, אין מפתח Tailscale, אין סיסמת Wi-Fi ואין מפתחות SSH של המכשיר. בעלייה הראשונה כל פיי מייצר לעצמו שם, מפתחות SSH, `machine-id` ו-`claim_secret`, כך ששני כרטיסים מאותו Image הם שני מכשירים שונים.

---

## 1. בנייה (במחשב Windows, פעם בגרסה)

צריך Docker Desktop פועל. הבנייה לוקחת 30–60 דקות.

```powershell
cd C:\D\PycharmProjects\neeman_music\music_agent
.\image\build.ps1                          # ה-tag החדש ביותר של הנגן, Image 1.0.0
.\image\build.ps1 -AgentRef v2.2.4 -ImageVersion 1.0.1
```

התוצאה מגיעה ל-`image\build\soundops-img-v1.0.0-agent-v2.2.4.img.xz`, יחד עם קובץ `.sha256`. בסוף הבנייה רצות בדיקות, והבנייה נכשלת אם מישהו מהן לא עובר:
- בדיקה עצמית (PASS/FAIL לכל רכיב);
- בדיקה שלא נשאר שום סוד בכרטיס.

את הקובץ שומרים ב-Drive פרטי, לא ב-GitHub.

`-LocalAgent` מכניס לכרטיס את הקוד המקומי של הנגן, כולל שינויים שלא נכנסו ל-commit. זה רק לבדיקה על פיי בדיקה. ללקוחות בונים תמיד מ-tag.

## 2. צריבה

1. Raspberry Pi Imager → **Choose OS** → **Use custom** → בוחרים את ה-`.img.xz`.
2. **בלי OS customisation.** כשהוא שואל "Would you like to apply OS customisation settings?", עונים **No**. ה-Image כבר מוגדר, וההתאמה של Imager לא נקראת בו.
3. צורבים. לכמה כרטיסים במקביל: balenaEtcher.

## 3. Wi-Fi (רק בסניף בלי כבל רשת)

אחרי הצריבה Windows מציג את הכרטיס ככונן בשם `bootfs`. פותחים בו את `soundops-wifi.txt` ב-Notepad, ממלאים את השורות ושומרים:

```
WIFI_SSID=שם-הרשת
WIFI_PASSWORD=הסיסמה
WIFI_HIDDEN=no
```

בעלייה הנגן שומר את הרשת ומוחק את הסיסמה מהקובץ. בראש הקובץ נכתב אם השמירה הצליחה. כבל רשת תמיד מועדף על Wi-Fi.

כשהמכשיר כבר מחובר, אפשר להחליף רשת מהדשבורד: עמוד המכשיר → רשת.

## 4. הפעלה ושיוך

1. מכניסים את הכרטיס, מחברים כבל רשת (או Wi-Fi כמו בסעיף 3) ואז חשמל. העלייה הראשונה לוקחת כ-2–3 דקות, כי המכשיר מרחיב את הדיסק ומייצר מפתחות.
2. בדשבורד: מכשירים → **מכשירים ממתינים**. המכשיר מופיע שם בשם `soundops-xxxxxx` עם קוד שיוך. אם הדפדפן ברשת של החנות, מופיע גם הסימון "ברשת שלך". **זהה** מהבהב בנורה הירוקה.
3. **שייך** → בוחרים סניף. תוך כחצי דקה המכשיר פעיל, ומנגן רק אם יש לסניף תזמון פעיל.
4. אחרי השיוך, אם Tailscale מוגדר בשרת (סעיף 5), המכשיר מצטרף לחשבון Tailscale בתוך דקה. זה מופיע בעמוד המכשיר → רשת → "גישה מרחוק (Tailscale)".

עדכוני גרסה של הנגן נעשים מהדשבורד כרגיל. Image ישן לא מחייב לצרוב מחדש.

## 5. Tailscale: הגדרה חד-פעמית

המטרה: כל נגן ששויך מצטרף לבד לחשבון Tailscale שלך, ואפשר להתחבר אליו ב-SSH מכל מקום, מהנייד או מהמחשב, בלי סיסמה ובלי מפתח.

**א. Access controls** (https://login.tailscale.com/admin/acls). מוסיפים ל-policy, ליד מה שכבר יש בו:

```json
"tagOwners": {
  "tag:soundops": ["autogroup:admin"]
},
"ssh": [
  {
    "action": "accept",
    "src":    ["autogroup:admin"],
    "dst":    ["tag:soundops"],
    "users":  ["pi", "root"]
  }
]
```

אם כבר יש ב-policy בלוק `"ssh"` (יש אחד בברירת המחדל), מוסיפים את הכלל לרשימה הקיימת. לא יוצרים בלוק `"ssh"` שני.

**ב. OAuth client** (https://login.tailscale.com/admin/settings/oauth → Generate OAuth client):
- Scopes: **Auth Keys → Write**.
- Tags: **`tag:soundops`**.
- שומרים את ה-Client ID ואת ה-Secret. ה-Secret מוצג פעם אחת בלבד.

**ג. Coolify** (השרת): מוסיפים משתני סביבה ועושים redeploy.

```
TAILSCALE_OAUTH_CLIENT_ID=...
TAILSCALE_OAUTH_CLIENT_SECRET=...
```

רק השרת מחזיק את ה-Secret. לכל מכשיר הוא יוצר מפתח חד-פעמי שפג אחרי 10 דקות. המפתח לא נשמר במסד הנתונים ולא ביומן הפעולות: שם הוא מוצג כ-`***`.

**ד. התחברות**
- במחשב או בנייד מתקינים את Tailscale ומתחברים לאותו חשבון.
- מתחברים מכל אפליקציית SSH (בנייד: Termius, למשל):

```
ssh pi@soundops-<סניף>-<6 תווים>      # השם מופיע בעמוד המכשיר → רשת
```

שמות המכשירים ב-Tailscale הם `soundops-<מספר סניף>-<6 תווים אחרונים של המספר הסידורי>`. מכשירים עם tag לא פגים, ולכן אין צורך לחדש אותם.

מכשיר שלא הצטרף (למשל כי Tailscale הוגדר בשרת אחרי השיוך): כפתור **חבר עכשיו** בעמוד המכשיר → רשת. חוץ מזה, השרת מנסה שוב לבד כל 30 דקות.

> פיי שהותקן בעבר ב-`setup.sh` לא כולל Tailscale. הדשבורד מציג אצלו "לא מותקן". זה מגיע רק עם ה-Image.

## 6. בעיות

| מה רואים | מה לבדוק |
|---|---|
| לא מופיע בממתינים אחרי 5 דקות | כבל רשת מחובר, הנורה הירוקה מהבהבת בעלייה, הראוטר נותן DHCP. ב-Wi-Fi: מה כתוב בראש `soundops-wifi.txt` כשמכניסים את הכרטיס למחשב |
| Tailscale "לא מחובר לחשבון" אחרי השיוך | המשתנים ב-Coolify, ה-tag ב-OAuth client וב-`tagOwners`. אחר כך **חבר עכשיו** |
| Tailscale מחובר אבל SSH נדחה | כלל ה-`ssh` ב-Access controls (סעיף 5א) |
| פיי שנצרב מחדש לא נשייך | בדשבורד בעמוד המכשיר הישן: **שחרר מכשיר**. הוא חוזר לממתינים עם הסוד החדש |
| ברשת המקומית, בלי Tailscale | `ssh pi@soundops-xxxxxx.local` עם המפתח שלך (המכשיר מכריז את השם ב-mDNS) |

## קבצים

| קובץ | מה הוא עושה |
|---|---|
| `build.ps1` | נקודת הכניסה ב-Windows: מריץ את הבנייה ב-Docker |
| `build-image.sh` | בתוך הקונטיינר: מוריד ובודק את Raspberry Pi OS, מגדיל אותו, מריץ את ההתקנה, מנקה זהויות, מכווץ ודוחס |
| `prepare-rootfs.sh` | בתוך ה-Image (chroot, ARM): מתקין חבילות, Tailscale, את הנגן, venv ו-Deno, מגדיר שירותים ומריץ בדיקה עצמית |
| `files/` | קבצים שמועתקים כמו שהם ל-Image: יחידות systemd, `firstboot.sh`, Wi-Fi מהכרטיס, SSH, journald, WirePlumber |
